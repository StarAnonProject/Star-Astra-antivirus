# StarAstra — антивирус Sentinel с современным дашбордом

StarAstra — это интерфейсный слой над антивирусным движком **Sentinel Antivirus**
(реальный мониторинг файлов, YARA + ML-классификация PE, карантин, защита от
заморозки системы — Anti-Freeze Guard).

> Честно о v1.0: сканирование памяти и canary-ловушки в текущей версии движка
> **не работают и отключены** (см. «Известные ограничения»).

Дашборд работает **без установленного Python**: всё нужное уже внутри.

---

## Установка

### Вариант 1 — установщик (рекомендуется)
1. Запустите `StarAstra-Setup-1.0.0.exe`.
2. Нажмите «Установить». Ярлыки появятся в меню «Пуск» и (по желанию) на рабочем столе.
3. После установки StarAstra запустится сам.

Установка выполняется в профиль пользователя (`%LOCALAPPDATA%\Programs\StarAstra`)
и **не требует прав администратора**: антивирус хранит свою историю и карантин
рядом с программой, а в Program Files запись запрещена Windows.

### Вариант 2 — портативная папка
1. Скопируйте всю папку `StarAstra` в любое место, доступное для записи
   (например, `D:\StarAstra`). Не кладите её на Рабочий стол или в Документы —
   эти каталоги антивирус защищает, и он будет тратить время на собственные файлы.
2. Запустите `StarAstra.exe`.

> Обновление: распакуйте новую версию в чистую папку и запустите — история,
> карантин и настройки (файл `starastra_settings.json`, папки `data/`,
> `sentinel_pkg/sentinel/data/`) переносятся простой заменой каталога.

## Запуск

- `StarAstra.exe` — запускает защиту (движок) и открывает окно дашборда.
  Повторный запуск не создаёт вторую копию: окно просто поднимается наверх.
- В системном трее всегда висит зелёная звезда — признак работающей защиты.
  Закрытие окна (крестик) сворачивает программу в трей — защита продолжается.
  Если процесс дашборда с треем завершился аварийно, сторож вернёт его сам.
- Полный выход: иконка в трее → «Выход» (движок будет остановлен).
- Галочка «Автозапуск» в Настройках включает старт защиты при входе в Windows.

При старте дашборд проверяет движок и при необходимости запускает его сам
(до 10 секунд). За живостью движка следит встроенный сторож: если защита
упала или зависла, она автоматически перезапускается (кроме паузы/выхода).
Сторож также поддерживает иконку в трее и следит, чтобы процессы, внесённые
в исключения, не оставались замороженными (ложные срабатывания C2-эвристики
движка снимаются в течение пары секунд).

**Anti-Freeze Guard**: движку запрещено замораживать и убивать системные
процессы и процессы StarAstra (белый список: браузер, explorer, svchost,
поиск/shell и др.). Попытки движка блокируются и пишутся в `data\engine.log`
(`[Anti-Freeze Guard] Blocked ...`), а резервный поток-страж каждую секунду
возвращает к жизни всё, что из белого списка всё-таки уснуло.

## Сканирование

- **Быстрое** — память всех процессов, автозагрузка, «рискованные» каталоги
  (Загрузки, Рабочий стол и т.п.). Занимает несколько минут.
- **Полное** — все пользовательские файлы. Может идти долго (десятки минут).
- Во время скана видно прогресс и текущий файл; кнопка «Отменить» прекращает
  проверку.
- **По расписанию** (Настройки): ежедневный фоновый скан в выбранное время —
  без открытия окна, результат приходит уведомлением и в Истории.
  Если в назначенное время защита была на паузе или уже шёл ручной скан,
  плановый скан сдвигается на ближайший свободный момент (не отменяется).

## Поведенческий анализ (v1.0)

Помимо сканирования файлов, StarAstra следит за **поведением процессов**:
Office, запустивший оболочку; известные «LOLBin»-утилиты (certutil, mshta,
rundll32…); PowerShell со скрытой/закодированной командой; скрипты из Temp,
выходящие в сеть. При подозрении процесс **замораживается** (suspend), и
появляется карточка:

> ⚠️ Подозрительное поведение: [Процесс] заморожен. Причина: [Правило].

- **[Убить]** — завершить процесс окончательно.
- **[Разрешить]** — разморозить и добавить процесс в исключения
  (больше не тревожится). Появится в списке исключений в Настройках.
- Режим переключается в Настройках → «Поведенческий анализ»:
  **«Останавливать подозрительные процессы»** (по умолчанию) или
  **«Только уведомлять»** (audit — ничего не замораживается).
  Применяется без перезапуска.
- Доверенные процессы (explorer.exe, браузеры, системные — whitelist
  Anti-Freeze Guard) **никогда не замораживаются**.

## Если найден вирус

1. Появляется карточка угрозы и системное уведомление с оценкой (score) и
   путём к файлу.
2. Движок автоматически:
   - приостанавливает атакующий процесс (угрозы в памяти, шифровальщики);
   - помещает подозрительный файл в **карантин** (шифрованное хранилище).
3. Ваши действия (раздел «Карантин»):
   - **Восстановить** — если это ложное срабатывание (файл вернётся на место);
   - **Удалить навсегда** — если угроза реальная.
4. Карантинная запись с оценкой ≥ порога обрабатывается автоматически;
   ручные кнопки — для спорных случаев.

Если антивирус «ругнулся» на ваш легитимный файл (ложное срабатывание), добавьте
исключение в Настройках (путь / хеш / имя процесса). За изменениями списка
следит защита: внешнее изменение исключений фиксируется как событие HIGH.

## Обновления

Кнопка «Проверить обновления» (Настройки) фиксирует время проверки.
Сервер обновлений пока не настроен — о новых версиях сообщит страница проекта.

## Где что искать

| Что | Где |
|---|---|
| История угроз и событий | Дашборд → «История» (и база `sentinel_pkg\sentinel\data\events.db`) |
| Карантин | Дашборд → «Карантин» (база `sentinel_pkg\sentinel\data\quarantine.db`) |
| Действия пользователя (журнал) | Настройки → «Журнал действий» (файл `data\audit.log`) |
| Лог дашборда/лаунчера | `data\launcher.log` |
| Лог движка | `data\engine.log` |
| Лог сторожа | `data\watchdog.log` |
| Настройки | `starastra_settings.json` (язык, расписание, исключения, пауза) |

Свои действия (сканы, пауза, карантин, исключения, смена языка) пишутся в
«Журнал действий» — с фильтром по типу.

## Проверка защиты (для любопытных)

- **EICAR-тест**: запишите на Рабочий стол (или в Загрузки) тестовую строку
  из стандарта EICAR (см. eicar.org — «The Anti-Virus test file»; начинается
  на `X5O!P%@AP` и заканчивается `$H+H*`) с расширением `.com` — защита
  обнаружит его за секунды (YARA-правило, оценка 85–90), пришлёт
  уведомление и отправит в карантин.
  Примечание: сам файл README этой строки не содержит — иначе его
  «заразит» собственная документация.

## Известные ограничения (v1.0)

1. **Движок может ложно реагировать на сетевую активность** (торренты,
   браузеры помечаются как «C2-канал»), но **Anti-Freeze Guard предотвратит
   зависание системы**: попытки движка заморозить/убить системные процессы
   блокируются и логируются, резервный страж каждую секунду оживляет
   whitelisted-процессы. Сеть при этом не страдает.
2. **Сканирование памяти и Canary-ловушки отключены** — текущая версия
   движка их не поддерживает (не детектирует инъекцию в память и не
   доводит сигнал ловушек до реакции). В Настройках эти функции показаны
   серыми с пометкой «Не поддерживается текущей версией движка».
3. **Если антивирус начал мешать работе** — используйте кнопку «Пауза»
   в трее (подменю на 10–60 минут) или в дашборде: защита остановится
   и не будет перезапускаться, пока пауза активна.

Также: проверка обновлений — заглушка (сервер не настроен); отмена скана
завершает процесс сканера (плавной паузы скана нет); сторож не защищён сам
от удаления (он ловит «движок умер/завис», а не «убили сторожа»).

## Требования для разработчиков / Установка из исходников

Репозиторий содержит только **исходный код StarAstra**: UI, лаунчеры,
поведенческий анализ, сторож, i18n, уведомления и скрипты сборки.
Бинарники движка Sentinel в репозиторий не входят — их нужно скачать отдельно.

### 1. Что нужно

- **Windows 10/11**.
- **Python 3.12** — движок Sentinel собран под 3.12; на Python 3.14+
  модули `sentinel.engine.*` не импортируются (UI запустится, но только
  в режиме чтения).
- Оригинальный дистрибутив **Sentinel Antivirus** (движок от StarAnonProject).

### 2. Скачать движок Sentinel

1. Скачайте оригинальный дистрибутив Sentinel.
2. Скопируйте папку **`sentinel_pkg`** из дистрибутива в **корень** этого
   проекта (рядом с `starastra_launch.py`).
3. Если в дистрибутиве есть папка **`Sentinel\_internal`** (ML-зависимости и
   модели: numpy / scipy / scikit-learn / lightgbm / YARA) — положите её в
   `Sentinel\_internal`. Если её нет, зависимости движка установятся из
   `requirements.txt`.

Итоговая структура:

```
StarAstra-Source\
├── sentinel_pkg\                     ← из дистрибутива Sentinel (не в git)
├── Sentinel\
│   ├── _internal\                    ← рантайм движка (не в git)
│   └── ui\starastra_dashboard.py     ← наш UI (в репозитории)
├── starastra_behavior\
├── starastra_i18n\
├── starastra_notify\
├── starastra_ui\
├── starastra_launch.py
├── requirements.txt
└── ...
```

### 3. Виртуальное окружение и зависимости

```bat
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

### 4. Запуск из исходников

```bat
StarAstra.bat
```

Только движок (без окна):

```bat
.venv\Scripts\python starastra_launch.py --engine-only
```

Диагностика состояния:

```bat
.venv\Scripts\python starastra_launch.py --status
```

### 5. Сборка exe и установщика

```bat
build_exe.bat          :: портативная папка dist\StarAstra
build_exe.bat test     :: + смоук-тест чистой копии
```

Установщик: `ISCC.exe installer.iss` (Inno Setup 6).
Подробности — в `LAUNCHER.md`.

> `starastra_settings.json` в репозитории — **шаблон настроек по умолчанию**
> (язык, пауза, расписание, исключения). При запуске UI дописывает туда
> машинно-зависимое состояние; при необходимости исключите файл из
> отслеживания (`git update-index --skip-worktree starastra_settings.json`).
